# web-access Skill

## 浏览哲学

**像人一样思考，带着目标进入，边看边判断。**

1. **明确目标**：用户要什么？事实结论、正文摘要、还是决策依据？先写下成功标准再动手。
2. **选择起点**：根据已有线索（URL / 关键词）选最可能直达的一个工具试一次，不要堆方案。
3. **过程校验**：每一步结果都是证据。404、空正文、防爬提示都是有效信息，**不要在同一条路径上反复重试**。
4. **完成判断**：拿到目标内容就停；一个高质量摘要优于抓十个无关页面。

## 工具选择表

| 场景 | 首选 | 说明 |
|---|---|---|
| 搜索关键词、找入口、查最新信息 | `web_search` | 需要配置搜索 provider；未配置时会提示不可用 |
| URL 已知，目标是正文（博客 / 官方文档 / README） | `web_fetch` | 抓取并提取 Markdown 正文 |
| 搜索到有用链接后需深入阅读 | 先 `web_search`，再 `web_fetch` | 两阶段：找链接 → 读全文 |
| 本地代码问题 | `glob_files` / `grep_code` | 不要误用联网工具 |

## 推荐流程

```
1. 无 URL → web_search 获取候选链接
2. 有 URL → web_fetch 抓取正文
3. 正文足够 → 直接回答用户
4. 正文不足 → 可再 search 补充，但避免对同一 URL 反复 fetch
```

## 边界与约束

- `web_fetch` 适用于静态或 SSR 页面；若返回空正文或极短内容，可能是 JS 渲染页，**告知用户边界**，不要无限重试。
- `web_search` 依赖环境配置（SerpAPI / SearXNG 等）；不可用时说明限制，可请用户提供 URL 改用 `web_fetch`。
- 联网结果应标注来源 URL；不要把搜索结果当作已验证事实，必要时交叉核对。
- 本地仓库内的代码、配置、测试问题仍优先项目内工具，不要先上网搜索。

## 输出建议

- 搜索任务：列出 3–5 条高相关结果 + 简短结论。
- 阅读任务：摘要核心观点 + 关键引用 + 来源链接。
- 版本/文档查询：给出查到的版本号或日期，并注明查询时间。
